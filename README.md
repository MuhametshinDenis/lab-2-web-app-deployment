# Лабораторная работа № 2. Развёртывание веб-приложения

## Цель работы

Получение практического опыта администрирования сервера в условиях недостатка исходной информации. Исследование неизвестного веб-приложения, определение требований для его работы, установка и настройка необходимого программного обеспечения, развёртывание приложения на виртуальном сервере под управлением Ubuntu Server.

## Исходные данные

В качестве сервера используется виртуальная машина, подготовленная в предыдущей лабораторной работе.

Исходное состояние сервера:
- Установлена операционная система Ubuntu Server.
- Настроено сетевое подключение.
- Обеспечен удалённый доступ по SSH.

Полученный архив с веб-приложением содержит два каталога:

- `client/` — клиентская часть приложения.
- `server/` — серверная часть приложения.

Инструкция по установке и запуску отсутствует. Используемые технологии, зависимости и требования к окружению необходимо определить самостоятельно.

## Задачи

1. Исследовать структуру проекта и определить назначение его основных компонентов.
2. Определить используемые языки программирования, фреймворки, программные платформы и зависимости.
3. Установить необходимое программное обеспечение на сервер.
4. Подготовить клиентскую часть приложения к запуску.
5. Настроить и запустить серверную часть приложения.
6. При необходимости установить и настроить систему управления базами данных.
7. Настроить взаимодействие между компонентами приложения.
8. Обеспечить сетевую доступность приложения с хост-машины.
9. Проверить работоспособность приложения через веб-браузер.

## Архитектура приложения

Веб-приложение может состоять из нескольких взаимодействующих компонентов:

- **Клиентская часть** — отвечает за отображение пользовательского интерфейса и взаимодействие с пользователем.
- **Серверная часть** — обрабатывает запросы, выполняет прикладную логику и взаимодействует с другими компонентами системы.
- **База данных** — обеспечивает хранение информации, если она используется приложением.
- **Дополнительное программное обеспечение** — среды выполнения, библиотеки, веб-серверы и другие необходимые зависимости.

Фактический состав системы определяется в процессе исследования проекта.

Пример взаимодействия компонентов:

```text
Браузер
   |
   v
Клиентская часть
   |
   v
Серверная часть
   |
   v
База данных
```

Конкретная схема взаимодействия зависит от реализации приложения.

## Требования к результату

После завершения лабораторной работы необходимо обеспечить выполнение следующих условий:

- Установлено всё необходимое программное обеспечение.
- Клиентская и серверная части приложения подготовлены и настроены.
- База данных настроена, если она необходима для работы приложения.
- Необходимые процессы запущены и функционируют корректно.
- Настроено сетевое взаимодействие между компонентами.
- Приложение доступно с хост-машины через веб-браузер по IP-адресу виртуального сервера.
- Основная функциональность приложения работает корректно.

## Диагностика и устранение ошибок

При возникновении проблем рекомендуется последовательно проверять компоненты системы:

- Анализировать структуру проекта и конфигурационные файлы.
- Проверять наличие необходимых зависимостей.
- Проверять состояние запущенных процессов и служб.
- Изучать сообщения об ошибках и журналы приложения.
- Проверять сетевые настройки, адреса и используемые порты.
- Проверять доступность базы данных и параметры подключения, если она используется.
- Тестировать отдельные компоненты для определения причины неисправности.

Изменения конфигурации следует выполнять осознанно, понимая их назначение и влияние на работу системы.

## Ожидаемый результат

Работающее веб-приложение, развёрнутое на виртуальном сервере под управлением Ubuntu Server и доступное с хост-машины через веб-браузер по IP-адресу сервера.

По результатам работы необходимо понимать:

- Архитектуру развёрнутого приложения.
- Назначение основных компонентов системы.
- Причины установки конкретного программного обеспечения.
- Принципы взаимодействия клиентской части, серверной части и базы данных.
- Особенности конфигурации приложения.
- Причины возникших проблем и способы их устранения.

## Отчёт по лабораторной работе

Отчёт должен содержать:

- Описание исходного состояния сервера.
- Описание структуры приложения и используемых технологий.
- Перечень основных компонентов развёрнутой системы.
- Описание процесса установки и настройки программного обеспечения.
- Описание возникших проблем и способов их решения.
- Описание конечной конфигурации сервера.
- Подтверждение работоспособности приложения.

Основное внимание следует уделить обоснованию принятых решений, объяснению внесённых изменений и пониманию принципов работы развёрнутой системы, а не простому перечислению выполненных команд.
